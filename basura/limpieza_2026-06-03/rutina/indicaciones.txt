Actúa como arquitecto senior de rutinas operativas, Supabase y generación incremental.

Objetivo:
Corregir la rutina del generador para que soporte generación recurrente de nuevos lotes.

Problema actual:
La rutina es idempotente sobre el mismo lote. Si ya existe `preguntas_finales.json` con 80 candidatos y esos fingerprints ya están en Supabase, la rutina solo audita el batch existente y mantiene 80. Eso evita duplicados, pero impide generar nuevos lotes.

Lo que necesito:
Mantener la idempotencia para el mismo lote, pero agregar un modo explícito `new-batch` que genere otros 80 candidatos nuevos, distintos a los ya cargados en Supabase.

Regla correcta:
- Mismo lote → no duplicar, emitir CHECKPOINT IDEMPOTENCIA.
- Nuevo lote → generar 80 nuevos, subirlos, Supabase pasa de 80 a 160, luego 240, etc.

Implementar:

1. Agregar comando npm:

```json
"qgen:new-batch": "node scripts/question-generator/run.js new-batch"
````

2. Agregar fase/comando `new-batch` en `run.js`.

Debe:

* detectar el batch local actual;
* mover los archivos vivos del lote anterior a una carpeta histórica;
* crear un nuevo estado limpio;
* conservar el corpus histórico;
* forzar nueva lectura de Supabase;
* tratar todos los candidatos ya cargados en `generated_topic_candidates` como existentes;
* generar 80 candidatos nuevos con fingerprints no usados;
* mantener 16 topics × 5 candidatos;
* ejecutar flujo normal hasta prepare/apply/audit según la rutina.

3. Crear carpeta histórica por batch:

```text
data/question-generator/batches/<batch_code>/
```

Mover ahí, si existen:

```text

preguntas_validas.json

preguntas_finales.json

apply_upload_result.json

ortografia_resultados.md
upload_result.json
```

No borrar sin archivar.

5. Mantener o regenerar corpus:

La rutina debe volver a leer Supabase, incluyendo:

* `temas`
* `tema_sugerencias`
* `generated_topic_candidates`

Muy importante:
Los 80 candidatos anteriores ya cargados en Supabase deben entrar al corpus anti-duplicado.

6. Anti-duplicado para nuevo lote:

Al generar nuevo batch, comparar fingerprints contra:

* preguntas existentes;
* sugerencias existentes;
* todos los `generated_topic_candidates` anteriores;
* candidatas del batch actual;
* válidas del batch actual;
* finales del batch actual.

Si fingerprint ya existe, rechazar y generar reemplazo.

7. Agregar dos modos explícitos:

## Modo resume

Comando existente:

```bash
npm run qgen:precheck
npm run qgen:generate
...
```

Comportamiento:

* retoma el lote actual;
* si los 80 ya están cargados, NO duplica;
* emite:

```text
CHECKPOINT IDEMPOTENCIA ✅
```

## Modo new-batch

Nuevo comando:

```bash
npm run qgen:new-batch
```

Comportamiento:

* archiva lote anterior;
* reinicia estado vivo;
* relee corpus remoto;
* genera un lote nuevo;
* permite subir otros 80 candidatos nuevos.
